## T1.1 CubeMX：UART1 + DMA 接收 + 空闲中断

- **目标**：实现"不定长数据接收"——串口上来的任意长度数据都能完整收下来
- **要搞懂的问题**（自己搜资料回答）：
  - 为什么需要 DMA + 空闲中断？相比阻塞收发好在哪？
  - 空闲中断（IDLE）在什么时刻触发？
  - `HAL_UARTEx_ReceiveToIdle_DMA` 是什么？你的 HAL 版本支持吗？（不支持就手动处理 IDLE 中断）
  - DMA 用 Normal 还是 Circular 模式？区别是什么？
- **自查**：串口助手发任意长度字符串，调试器里看到完整落进缓冲区、长度变量正确
- **重点坑**（这些坑一定会遇到）：
  1. 每次收完必须**重新挂起接收**，否则只能收第一包
  2. "重新挂起"的时机要小心（回调里还是主循环里），时机不对会丢包或踩内存
  3. DMA 缓冲区被覆盖：主循环还没处理完，新数据又写进来
  4. 网上代码不一定是给你这颗芯片写的，注意甄别 HAL 行为差异
- **验收**：.ioc 配置截图 + 接收成功的调试证据

## T1.2 数据解耦：缓冲与处理分离

- **目标**：中断只负责"搬数据"，主循环专门"解析数据"，两者互不阻塞
- **要搞懂的问题**：
  - 环形缓冲区（ring buffer）头尾指针怎么设计？"满/空"怎么判断？
  - 单生产者（中断）单消费者（主循环）时，指针读写什么时候是安全的？
  - `volatile` 解决什么问题？又解决不了什么问题？
- **务实路径**：先不搞环形缓冲——中断里直接往数组搬，主循环扫描处理，跑通后再重构
- **自查**：连续快速发 3 包不同长度数据，主循环按序完整处理
- **验收**：串口日志（3 包完整处理记录）

## T1.3 通信协议设计（两步走）

**第一步：ASCII 行协议**（先跑通）——PC 发 `"A\n"` / `"B\n"`，STM32 按行解析，先把控制链路打通

**第二步：二进制帧协议**（正式版），必须满足：
- 自同步：接收方从数据流任意位置开始，都能找到帧边界
- 检错：校验失败的帧直接丢弃，不崩溃
- 变长：以后要能装坐标（两个 int16）等数据
- 候选结构（自己定）：`帧头(2B) | 长度(1B) | 类型(1B) | 数据(N) | 校验(1B)`

**要搞懂的问题**：
- 帧头选什么值不容易误判？
- 校验算法选 和校验 / 异或 / CRC8 哪个？各自防什么错？
- 多字节数据的大小端要不要约定？
- 粘包 / 半包怎么处理？（一帧被拆成两次收到、两帧挤在一次收到）→ 状态机

- **自查**：
  - 故意发半帧、错校验帧 → 接收方能丢弃且不崩
  - 连续高频发 100 帧 → 不丢帧、不乱序
- **验收**：`docs/COMM_PROTOCOL.md` —— 自己写：帧格式表格、字段含义、校验算法、示例帧、粘包半包处理说明

## T1.4 PC 控制 LED（PySerial）

- **目标**：Python 脚本发命令，板子上 LED 跟着亮/灭
- **要搞懂的问题**：pyserial 的 `Serial` 参数（baudrate、timeout 各是什么）？收发的数据是 bytes 还是 str？timeout 设 0 / None / 正数的区别？
- **自查**：
  - 脚本反复运行正常（串口被正确释放）
  - 拔掉板子再跑脚本：给出友好报错而不是卡死
- **验收**：控制 LED 视频（evidence/stage1/）

## T1.5 STM32 回传心跳包

- **目标**：STM32 每 1 秒主动上报状态（LED 状态 + 递增计数即可）
- **要搞懂的问题**：主循环非阻塞定时怎么写（别用 HAL_Delay 卡死主循环）？HAL_GetTick 怎么用？发送用阻塞还是中断/DMA，各自代价？
- **自查**：PC 端稳定收到 1 Hz 心跳，计数连续无跳变
- **验收**：串口日志（连续多包心跳）

## T1.6 组合验收

- **目标**：PC 发 A/B 控制 LED + 实时接收解析心跳，**双向同时工作**
- **建议成果物**：PC 端一个"迷你终端"脚本（发命令 + 解析显示心跳）——这个脚本阶段 2/3 会持续进化，值得认真写
- **验收**：视频（LED + 终端同框最佳）+ 串口日志 → `evidence/stage1/`
- **收口**：更新 PROGRESS.md → `git commit` + `git tag stage1-done`

## 调试工具与排错顺序

- **串口助手**：SSCOM / XCOM 任选（做裸验证用），后面主要用自己写的 Python 脚本
- **printf 调试**：搜"STM32 printf 重定向"，把 log 从串口打出来——注意 log 和协议数据共用一个串口时要想好区分方式，或仅调试时开启
- **排错顺序**（别跳步）：物理层（接线/共地/波特率）→ 中断有没有进（断点或"点灯法"）→ 再查解析逻辑
